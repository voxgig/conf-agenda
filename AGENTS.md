# Agent guide: conf-agenda

> **The rules live in [`openspec/config.yaml`](openspec/config.yaml); read it before any task.**
> This file holds facts only: what exists, where, and why. Rules that used to be here are rules
> there now.

> Workflow (explore → propose → approve → apply → verify → PR → archive):
> [`openspec/`](openspec/) and the `/opsx:*` commands. One task group is one PR and one session.
> Status, the running instructions and every trap's evidence: [`HANDOFF.md`](HANDOFF.md).
> The reasoning behind each major design: [`docs/decisions/`](docs/decisions/).
> Concepts, how-tos and reference: [`docs/`](docs/). The web app has its own guide at
> [`web/AGENTS.md`](web/AGENTS.md).

A Voxgig system project: Seneca 4 microservices driven by an aontu model
(`backend/model/*.aon` compiled to `model.json`).

## The specs are a different repo

`metsitaba/project-specs`, checked out at `~/project-specs`: `PLATFORM.md` plus
`conf-agenda/SPEC.CONF-AGENDA.md`, `ARCHITECTURE.md` and `MOCKUPS.md`. Read it freely. It is
**read-only**: a spec defect is written up in `docs/decisions/to-raise-upstream.md` and raised
with the maintainer, never as a PR against that repo.

## Commands

```bash
# backend/
npm run build         # model-build (compile model + codegen) + tsc
npm run model-build   # just compile the model + run generation
npm test              # unit tests (in-memory store, no externals)
npm run model-check   # model consistency checks
npm run local         # boot the backend locally
npm run web           # boot backend + SPA on :50500, seeds itself
# dev REPL on conf.port.repl (default 50502) in local+web runners:
#   npx seneca-repl telnet://localhost:50502   (REPL=false disables)

# web/
npm run build && npm test     # SPA build + node:test unit suite
npm run e2e                   # Playwright (see HANDOFF.md for the browser path)

# embed/
npm run build && npm test     # test = build + size budget + render suite
npm run size                  # the size budget on its own (tool/size-check.mjs)

# repo root (tooling only)
openspec validate --all --strict
```

## Layout

| | |
|---|---|
| `backend/model/` | the model sources: `ent.aon` (entities), `srv.aon` (services), `msg.aon` (messages), `env.aon` (environments), `theme.aon` (design theme), `conf.aon` (config), `ontology.aon` |
| `backend/src/srv/<srv>/` | service actions; a model message maps to the file named after its LAST pattern pair (`save:item` → `save_item.ts`) |
| `backend/src/concern/` | cross-service concerns (`CalendarSync/`, `FixtureTree/`) |
| `backend/src/lib/` | pure helpers (`publish_diff.ts`, `contrast.ts`, `assets.ts`, `eventspec.ts`) |
| `backend/src/env/` | runtime entries (`shared`/`local`/`lambda`/`web`) |
| `backend/build/` | local model-build generators, including `msg_meta.js` |
| `backend/bin/conf-agenda.mjs` | the CLI (`validate`, `publish`, `feed`, `eject`) |
| `backend/mcp/server.mjs` | the read-only MCP server, four §14 tools |
| `backend/test/fixtures/` | `tiny`, `demo` (both seeded) and `nodeconf` (the real programme, not seeded) |
| `web/` | the generated SPA. `src/cmp/view/cag_fixture.js` is the agenda grid |
| `embed/` | the framework-free `<conf-agenda>` component |
| `backend/asset/` | generated by `backend/tool/copy-embed.mjs` during `npm run build`: the embed's UMD build, shipped in every ejected bundle as `conf-agenda.js`. Gitignored |
| `sdk/` | the generated client chain |
| `openspec/` | the planning store and the rule store |

**Generated vs yours.** `backend/gen/` and `model/model.json` are regenerated every model-build
and are never hand-edited. `backend/src/`, `web/`, `embed/` are create-once: yours to edit
freely. `.agents/skills/openspec-*`, `.claude/skills/openspec-*` and `.claude/commands/opsx/*`
are generated by the openspec CLI and refreshed with `openspec update`.

**`embed/dist` is a backend build input.** `backend` `npm run build` copies
`embed/dist/conf-agenda.umd.cjs` into `backend/asset/` and fails, naming `cd embed && npm run build`,
when it is missing. Build `embed/` first on a clean checkout.

## Load-bearing pieces worth knowing about

| | |
|---|---|
| `backend/build/msg_meta.js` | withholds `inverse` from the in-memory model, and must stay first in `sys: model: order: action` |
| `backend/src/srv/cag/ent_intent.ts` | the per-entity admin write intents and the `REFERENCED_BY` refusal |
| `backend/src/srv/cag/plan_publish.ts` | computes what publishing would change, without publishing |
| `backend/src/concern/CalendarSync/` | the ledger, the queue, the lock and the safety chain |
| `web/src/cmp/view/cag_fixture.js` | the grid, and the binding registry every keyboard surface reads |
| `web/src/undo.js` | `buildInverse`, pure, with its own unit tests |
| `web/src/chords.js` | the `g`-prefix chord reader, driven from the shell in the capture phase |
