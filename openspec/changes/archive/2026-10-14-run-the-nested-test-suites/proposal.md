## Why

`npm test` in `backend/` skips every test file below `dist-test/unit/` except one, so 30 tests
never run. Thirteen of them cover the live auth service and pass. The other seventeen look like
coverage of a surface this project removed. And any new test put in a subdirectory joins them in
silence. HANDOFF.md already queues this as "its own change, next".

## What is wrong today

- `backend/package.json:7`: the script globs `dist-test/unit/*.test.js` (one level) and names
  `dist-test/unit/env/web/api-router.test.js` by hand. Five compiled suites sit deeper and are
  never run.
- Run by hand on `main` at `8aa020f` (`node --test-force-exit --test dist-test/unit/<path>.test.js`):

  | suite | tests | pass | fail | what it covers |
  |---|---|---|---|---|
  | `srv/auth/apikey` | 5 | 5 | 0 | the live `auth` service (API keys) |
  | `srv/auth/session` | 8 | 8 | 0 | the live `auth` service (sign in, sign out, profile) |
  | `srv/api/api` | 8 | 0 | 8 | `aim:api,on:ent`, the generic REST entity service |
  | `srv/ent/proxy` | 4 | 3 | 1 | `aim:web,on:ent,cmd:*`, the generic browser proxies |
  | `env/web/surface` | 5 | 1 | 4 | reads `main.msg.aim`, which is now a list |

  That is 30 tests, 13 failing. HANDOFF.md:173 counts 25 and 9 because it leaves `surface` out.
- The failing tests assert the generic `ent` surface SPEC §9 replaced with named intents. The
  model declares only `agenda`, `auth` and `cag` in `main.srv`, and no `on:ent` or `aim:api`
  pattern in `main.msg`.
- **HANDOFF.md and the decision records disagree about where these files come from, and both
  are partly wrong.** HANDOFF.md:179 says "nothing regenerates them".
  `docs/decisions/web-env-and-generic-ent.md:45` says they are "regenerated byte-identically on
  every model-build". The source is `node_modules/@voxgig/build/dist/env/web/web_gen.js:104-116`,
  which lists all six nested suites, and `:191`, which skips any file that already exists. So
  they are **create-once**. Edit one and the generator leaves it alone. Delete one and the next
  model-build writes the generic version back.
- The trap is live: a rule in `openspec/config.yaml` (apply guidance, "A new test file goes at
  the top level...") exists only to work around it, and it caught `test/unit/lib/` during the
  eject work.

## What Changes

- **The test script globs recursively**: `dist-test/unit/**/*.test.js`, the same glob
  `test-some` already uses. The explicit `api-router` entry goes away because the glob now
  covers it.
- **`srv/auth/apikey` and `srv/auth/session` join the run unchanged** (13 tests).
- **The three dead suites keep their files but get new bodies**: each one asserts that the
  generic surface it used to cover is absent, plus a known-present case so it cannot pass
  vacuously. The file stays on disk, so the generator keeps skipping it.
  - `srv/api/api.test.ts`: `api` is not in `main.srv` and no `aim:api` pattern is declared.
    Known present: `cag` is in `main.srv`.
  - `srv/ent/proxy.test.ts`: `ent` is not in `main.srv` and no booted `cag` service answers
    `aim:web,on:ent,cmd:list`. Known present: the same seneca answers `aim:web,on:cag,load:tree`.
  - `env/web/surface.test.ts`: keeps its one passing test, the gateway allow-list read from
    `src/env/web/web.ts`, which no other suite covers. Its four model-walk tests go;
    `browser-surface.test.ts` already does that walk correctly over the list.
- **Docs and rules follow the facts**: the HANDOFF.md trap entry, the two decision records and
  the `config.yaml` rule that says subdirectory tests never run.
- The run goes from 360 tests to 378, all passing: 360, plus 13 auth tests, plus two each in
  `api` and `proxy`, plus the one gateway test kept in `surface`.

## Specs cited

- **PLATFORM §10** (quality floors): "A test that walks the model must be able to fail. Assert a
  known-present *and* a known-absent case". The new absence suites follow this.
- **PLATFORM §1.2** and **SPEC §9**: the generic entity surface was replaced by named intents.
  The absence suites now pin that in the files that used to test the old design.

## Decisions

- **The three dead suites: absence tests** (chosen by José). The alternatives were a tombstone
  with only a comment (simpler, but files that report 0 tests, which the repo's rules say is not
  a pass) and rewriting them against the named intents (mostly a copy of
  `srv-cag-intents.test.ts` and `browser-surface.test.ts`). Deletion is not an option, because
  the generator recreates any missing file.
- **How the run reaches nested suites: a recursive glob** (chosen by José). The alternative was
  listing the two auth files by name. That keeps the subdirectory trap and would need a guard
  test that every compiled file is listed.
- **Assumption, recorded here for review:** `surface.test.ts` keeps its one passing gateway test
  instead of becoming a pure absence test. The test is still valid and is the only check on the
  allow-list literal.

## Upstream

Nothing is blocked. One thing is worth telling the maintainer, but it is not a spec defect, so
it does not go in `to-raise-upstream.md`: `@voxgig/build`'s `web_gen` still writes the generic
`ent`/`api` suites into any project that does not declare those services. A project that
removes the generic surface (as todo-app and this repo both did) gets failing tests on its first
model-build.

**Found and left: the REST router posts a message nothing answers.**
`backend/src/env/web/api.ts:90` posts `aim:api,on:ent`, and no `api` service is declared, so a
real REST request gets no action. `api-router.test.ts` passes only because it mocks that
message. This change touches neither `api.ts` nor its test. A fix needs its own choice: route
REST onto the named intents, or remove the REST layer until it has a design. That is a fork for
José, so this PR records it in HANDOFF.md and does not fix it.
